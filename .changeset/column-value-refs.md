The main dataset, CD4/CD8 dataset, CD4/CD8 subset, design covariate, contrast factor and pairing metadata columns are stored as column ids of the result pool instead of references to upstream outputs or column labels, and the numerator and denominator groups as column value references to the contrast factor column, so the block that produced the metadata knows which of its values this block uses. The options of every column picker are built by the model. A CD4/CD8 subset column that is gone or whose values cannot be read keeps Run disabled and says why under its picker, instead of the block waiting for its values; why the values of the contrast factor column cannot be read is shown under the numerator and denominator pickers. Opening a project created before this change keeps the picked columns, converted to the new ids, and keeps the numerators and denominators, converted to column value references to the same contrast factor column. Picked values are always text, so a group picked from a numeric column still matches its value. Picks that cannot be converted are reset and must be picked again: the pairing metadata column, which was stored as a column label that names no producing block, and the numerators and denominators of a block that had no contrast factor column picked. Until the pairing metadata column is picked again, TCR alpha/beta pairs are found by the "Barcode ID" metadata column, as for a block that never had one picked. The initialization params of the kind carry the same column ids and references, so templates made for an earlier version of the kind cannot be applied.
Numerators and denominators that are no longer among the values of the contrast factor column stay selected and are marked as not available instead of being removed silently, with a tooltip naming the block that was to provide them, as a link to it, and what went wrong. Changing the contrast factor still clears them.
